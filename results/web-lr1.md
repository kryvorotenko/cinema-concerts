# Web ЛР1: результати перевірок

Дата: 2026-11-25. Це **локальний прогін без Docker Compose**; межі описано в кінці.

## Середовище

PostgreSQL 16 (пакет Ubuntu), нова база; усі міграції застосовано штатним `config/migrate/migrate.sh`
у порядку `001, 010, 011, 012, 020`, повторний `--list` показує їх застосованими. Два процеси
`uvicorn app.main:app` (`INSTANCE=app-a` на 8001, `app-b` на 8002) із `web/server`, Python 3.13
(образ проєкту використовує 3.14). DPC для наскрізного досліду — `api` з гілки `illia-dpc-lab6`
(`EXECUTION=local`, `TICKET_CHECK_MODE=web`, `WEB_API_URL` вказує на `app-a`); Ray встановлено лише для імпорту.
База спільна для Web і DPC: міграції `010–012` та фікстури DPC лежать поруч із даними Web.

## Відомі розбіжності з DPC (не виправляються в Web)

- Тіло `POST /v1/scans` з картки C01 не містить `ticket_code`, а DPC ЛР1–6 його вимагає (400 без нього; це відкритий
  пункт аудиту `dpc-scope-audit-2026-11-23.md`). Web уже приймає `ticket_id` у `GET /v1/tickets/{code}`, тож
  виправлення на стороні DPC — зробити `ticket_code` необов'язковим і підставляти `ticket_id`.
- DPC зберігає в `processed_effects` за `ticket_id` і відмови (`wrong_performance`, `sector_full`, `invalid_ticket`) та
  повторює їх для всіх наступних сканів. Перевірено: валідний `TKT-DEMO-0003`, один раз відсканований не в тому секторі,
  у правильному секторі відхиляється з тим самим рішенням. Для Web це означає, що квиток, відсканований до підтвердження
  оплати, лишиться відхиленим. Рішення за учасником 3.

## Чого не перевірено

- Збирання образу `project-web` (Python 3.14, `uv.lock`) і запуск через `docker compose` та nginx. Залежностей не додано,
  але перший прогін у Compose ще треба зробити й записати сюди; через nginx DPC звертається до Web за `WEB_API_URL=http://nginx`.
- `web/client/index.html` не відкривали в браузері: перевірено синтаксис скрипта й модуль `api.js`.
- О1.6: перевірено `/health`, `X-Request-ID` і JSON-журнал екземплярів; запуск «однією командою» з nginx залежить від Compose.
- DPC з Ray (`EXECUTION=ray`) і координатор etcd не запускались: вони не торкаються Web ЛР1.
- Гонка 300/50 (О2.1), ідемпотентність (О2.2) і відмови (О2.3) — завдання ЛР2.
- Утримання «рівно 10 хвилин → прострочено» перевірено лише умовою `<=` у SQL, не окремим тестом за часом.

## Перевірено в Docker Compose (Windows, Docker Desktop)

- `docker compose up -d --build`: усі сервіси підняті, `/health` через nginx (:8080) відповідає `ok`.
- `experiments/test_web_lr1.py` через nginx: 41 перевірка пройдена, зокрема гонка з 20 паралельних запитів на 5 місць (5x201, 15x409, available=0).
- Браузерний клієнт (:8081): вхід як usr-alice, створення утримань (201), закрита категорія та нестача місць дають 409, список утримань оновлюється.
