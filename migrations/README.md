# Спільні міграції

`001_shared_foundation.sql` — спільний початковий контракт команди.
Запуск з кореня: `docker compose run --rm migrate`.
Версія та назва фіксуються у `schema_migrations`; повторний запуск пропускає
застосовані файли. Кожен звичайний SQL-файл виконується транзакційно.

Після спільного старту **не редагуйте 001**: додавайте `002_*.sql`, `003_*.sql`
та узгоджуйте унікальні номери в команді. Демо-акаунтів і фіктивних результатів
у початковій схемі немає. Бібліотечні приклади з web/dpc migrations/examples
не застосовуються спільним запуском.

Схема сама не реалізує операції: Web має атомарно змінювати available разом із
booking, DPC — inside разом із processed_effects. Наявність fencing_token не
замінює реєстрацію поколінь і транзакційну перевірку ресурсу в DPC ЛР6.
Поле seats та таблиця seats мають різний зміст: bookings.seats — кількість,
таблиця seats — майбутні конкретні місця Web ЛР6, поки порожня.
