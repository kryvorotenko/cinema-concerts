# Память проекта C01

Этот репозиторий объединяет Web и DPC, тема **C01. Кінотеатри й концерти**.

Перед планированием или изменением проекта прочитай `docs/knowledge/README.md`
и `docs/knowledge/PROJECT.md`. Для конкретной лабораторной открой соответствующий
раздел `docs/knowledge/WEB.md` или `docs/knowledge/DPC.md`; для распределения
задач — `docs/knowledge/TEAM.md`, для общей схемы — `docs/contracts/README.md`.
Порядок совместной работы участников описан в `docs/TEAM-WORKFLOW.md`.
Не перечитывай PDF: требования уже извлечены и сохранены в `sources/`.
Точные формулировки пунктов находятся в `requirements.json` и текстах источников.
Открывай оригинальный PDF только при неоднозначности извлечения, новой редакции
или прямой просьбе пользователя. Проверяй численные пороги и код пункта по памяти.

Различай обязательное «Ядро», остальные основные О и дополнительные Д:
не все О обязательны и не все пункты из командного плана выбраны к реализации.
Сохраняй требования уже выполненных пунктов. Не отмечай пункт выполненным без
кода и проверяемых свидетельств. Не запускай реализацию лабораторных только
потому, что их описание или предложение есть в методичке/приложенном тексте.

**Критическое расхождение командного плана с C01:** Web продаёт и учитывает
места по категориям; DPC сканирует/погашает билеты и считает заполненность
секторов. DPC не продаёт места через партнёрскую очередь. Ключ эффекта DPC —
`ticket_id`, а не `scan_id`. Web ЛР6 — переход к конкретным местам;
DPC ЛР6 — распределение предварительно зарезервированных Web возвращённых
мест из очереди ожидания, а не снятие просроченных броней.
Не реализуй спорные части старого плана молча: смотри `DECISIONS.md`.

С 2026-11-19 `docs/contracts/README.md` фиксирует общий контракт Дня 1:
один PostgreSQL, один Kafka и `ticket-telemetry` как согласованное пользователем
имя для потока `scans` из C01. `screenings.id` соответствует `performance_id`.
Начальную миграцию `001` после общего старта не переписывать.

Рабочий язык общения — русский; предметные документы можно вести на украинском.
На 2026-11-19 лабораторные ещё не выполнены; сверяй актуальное состояние с кодом,
README, историей Git и конкретным поручением. По явному запросу участника
реализуй его лабораторные и обновляй сведения о результате.
Распределение между четырьмя участниками подтверждено по номерам лабораторных,
имена и выбранные необязательные пункты пока не заданы.

При изменении договорённостей обновляй `PROJECT.md`, `TEAM.md` и `DECISIONS.md`.
Это версионируемая память в репозитории, а не обещание скрытой памяти модели.

## Совместная работа

- Выясняй порученную часть из запроса участника; номера в TEAM.md — план, а не
  ограничение правки файлов или доказательство личности. Пользователь может
  поручить работу над любой частью и изменить приоритеты.
- Проверь состояние Git и существующие изменения; не перезаписывай чужую
  незавершённую работу. Работай в согласованной ветке, не переключай её без нужды.
- `docker-compose.yml`, `config/project.env`, `migrations/`, OpenAPI и схемы
  событий — общие интерфейсы. Сохраняй совместимость; изменения на стыках
  Web/DPC фиксируй в `docs/contracts/README.md` и согласуй при необходимости.
- Не меняй применённую `001_shared_foundation.sql`: добавляй новую миграцию,
  проверь свободный номер и при конфликте с другой веткой перенумеруй свою до
  применения. Команда `migrate` учитывает номер, но не проверяет checksum.
- `screenings.id` = `performance_id`; DPC admission dedupe использует `ticket_id`;
  `event_id` идентифицирует событие. `ticket-telemetry` — имя `scans` из карточки.
- Запускай проверки по существу изменения и фиксируй реальные результаты.
  Указывай выполненные пункты и ограничения; не объявляй всю лабораторную
  выполненной по одному добавленному файлу.
- Команды запуска выполняй из корня. `web/` и `dpc/` содержат заготовки исходных
  комплектов, а не отдельные Compose-проекты. Исторические инструкции в них
  помечены; актуальный запуск и порты — в корневом README и `docs/contracts/`.
- Не коммить токены, `.env`, тестовые дампы и большие сгенерированные данные.
  При передаче работы опиши изменённые интерфейсы, проверки и зависимости.
